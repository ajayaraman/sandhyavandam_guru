# Sandhyavandanam Guru — Implementation Plan

## Context

The spec in `sandhyavandanam_app.md` asks for a terminal-based coach/guru that walks a (Rigveda, Tamil/Smarta) initiate through the **Pratah (morning) Sandhyavandanam** ritual end-to-end. The coach must:

1. Speak instructions in the user's native language (English first, Tamil-friendly later).
2. Play canonical Sanskrit mantras with clear, correct pronunciation.
3. Listen to the student reciting, gently correct mispronunciations, and otherwise advance.
4. Use **open-source, locally-runnable** audio + LLM models, served via **LM Studio** (OpenAI-compatible local API on `http://localhost:1234/v1`).
5. Have a **deterministic 26-step framework** so the ritual always goes from start to finish, regardless of LLM hiccups.

Why this design: mantra correctness is non-negotiable (religiously sensitive), so the ritual sequence and the mantra audio are **not** generated by an LLM at runtime. The LLM is restricted to coaching tone, empathy, paraphrasing of meaning, and judgement on whether the student's recitation is close enough to advance.

## Model stack (all local, all open)

| Role | Default choice | Rationale |
|---|---|---|
| **Sanskrit STT** (student recitation) | `faster-whisper` + **Sanskrit-transfer-learned Whisper** (~15 % WER on Vāksañcayaḥ). Forced `language="sa"`, expected Devanāgarī fed in as `initial_prompt`. | The only model with a *published* Sanskrit-mantra benchmark. Conservative default. |
| **Coach LLM** (empathy phrasing, gentle correction) | **Gemma 4 E4B** served by **LM Studio** at `http://localhost:1234/v1` (OpenAI-compatible). Pluggable alternates: Qwen2.5 7B, Llama 3.1 8B. | Only ever sees structured prompts (current step, similarity score, expected vs. heard text). LM Studio gives MLX acceleration on M-series and a simple OpenAI-shaped client. |
| **TTS** (English/Tamil instructions) | `piper-tts` (`en_US-lessac-medium`, `ta_IN-*`) | Tiny, instant, fully offline, very clear. |
| **TTS** (Sanskrit mantras — bootstrap only) | `Svara-TTS v1` | Generates first-cut mantra audio; manually validated before commit. |
| **Canonical mantra audio** | Pre-rendered `.wav` bank under `assets/mantras/`. User can replace any clip with a priest's recording (same filename). | Mantra correctness is religiously load-bearing; never generated at runtime. |
| **VAD** | `silero-vad` v5 (ONNX) | Standard, ~1 MB, tolerates chanting cadence with raised thresholds. |

### Validation gate before locking in: a one-day STT shootout (new Phase 0.5)

Because both Gemma 4 E4B audio and Whisper-Sanskrit are *plausible* but neither has a published Sanskrit-mantra benchmark we trust:

1. Build a 30-clip eval set: 10 short mantras (`om achyutāya namaḥ`-style), 10 medium (Gāyatrī ×1), 10 long (prāṇāyāma block). Each recorded twice — once by the user, once with deliberate small errors (vowel-length, missing aspirate). 60 clips total, under one hour of work.
2. Score each model on:
   - **CER** (character error rate, IAST-normalised).
   - **Religious-error recall**: does the model's transcript actually *differ* when the recitation differs in a meaningful place (aspirate, retroflex, visarga)? — this is what we need for "gentle correction" to work.
   - **Latency** on the user's hardware.
3. The model that wins on (religious-error recall × latency) becomes the Sanskrit STT. The other becomes the fallback. The result is written to `docs/stt_decision.md` and the default in `config.py` is set accordingly.

This costs ~1 day of work in Phase 0.5 and removes the biggest unknown in the architecture before we build the recitation-match step. If the user prefers to skip the shootout, we ship with Sanskrit-Whisper as the safer default — but we lose the chance to remove a dependency.

**Why Whisper-Sanskrit is the conservative default until the shootout**: it was *specifically* fine-tuned on Vāksañcayaḥ (Vedic recitation corpus). General multilingual models — Gemma 4 included — almost always trail dedicated low-resource fine-tunes for that exact reason. Don't bet on the generalist without proof.

**Hosting**: **LM Studio** serves the LLM (Gemma 4 default; Qwen / Llama swappable) over its OpenAI-compatible REST API. The Python client is the standard `openai` SDK with `base_url="http://localhost:1234/v1"` and a dummy API key. LM Studio's MLX runtime gives strong M-series performance, and its `lms` CLI lets `scripts/doctor.py` verify the server is up and the model is loaded. Piper / Whisper / Svara / silero are loaded directly via Python (LM Studio doesn't serve those today). For the Phase 0.5 shootout, Gemma 4 E4B's audio modality is reached through LM Studio's multimodal endpoint (image/audio attachment via the OpenAI `messages` schema).

## The 26-action deterministic framework (Pratah, Rigveda — bharatiweb.com source)

Taken **verbatim from the user-supplied canonical PDF** (`bharatiweb.com Rigveda Sandhyavandanam v1`). The PDF numbers 25 steps and inserts one unnumbered `aachamanam` between steps 24 and 25 — totalling **26 distinct actions**, matching the spec's "26 steps".

Encoded as YAML (`ritual/pratah_rigveda.yaml`). Each step has: `id`, `name_sa` (Sanskrit transliteration as in PDF), `name_en`, `posture` (face east/north/etc., sit/stand/squat), `physical_action`, `mantra_text` (exact transliterated chant), `mantra_id` (→ audio bank), `iast`, `devanagari`, `translation`, `repeat_count`, `advance_rule`.

| # | Sanskrit name | What happens |
|---|---|---|
| 1 | **aachamanam** | Sit squat, face east/north. Sip water 3× to `om achyutāya / anantāya / govindāya namaḥ`. Then 12 keśavādi names touching face/body parts. |
| 2 | **prāṇāyāma** | Alternate-nostril breath; mentally chant `om bhūḥ … satyam` + full Gāyatrī + `om āpo jyotiḥ …`. |
| 3 | **saṅkalpam** | Declaration: `mama upātta samasta durita kṣaya dvārā śrī parameśvara prītyartham — prātaḥ sandhyām kariṣye`. |
| 4 | **mantra-prokṣaṇam** | Write `om` on water saying `om keśavāya namaḥ`, sprinkle on head with the 9 `āpohiṣṭhā…` mantras, then on feet, head again. |
| 5 | **prāśanam** | Sip water with `sūryaśca mā manyuśca …` (morning-specific). |
| 6 | **aachamanam (2nd)** | Three name-sips again (`achyuta / ananta / govinda`). |
| 7 | **punaḥ prokṣaṇam** | Sprinkle again with `dadhikrāvaṇṇo akāriṣam …` followed by `āpo hiṣṭhā` repeat + `ṛtañca satyañca …` cosmic origin verse. |
| 8 | **arghya-pradānam** | Standing, face east; pour water from joined palms 3× with the full Gāyatrī. |

| 10 | **aikyānusandhānam** | Sit, close eyes, chant `asāvādityo brahma — brahmaivāhamasmi`. |

| 17 | **gāyatrī-upasthānam** | Prāṇāyāma (17.1) then standing prayer asking Gāyatrī to return to her abode (17.2). |

| 19 | **samaṣṭi abhivādanam** | Four rotational namaskaras to Sandhyā/Sāvitrī/Gāyatrī/Sarasvatī + the `kāmo'kārṣīt manyurakārṣīt` + **personal abhivādanam declaring pravara/gotra/sūtra/veda/name** ("`abhivādaye … rṣeya pravarānvita … gotra … sūtra … veda adhyāyī … śarmaṇām aham asmi bhoḥ`"). |

## Core control flow

`engine.py` runs a deterministic state machine. For each step:

1. Render step header in TUI; display Sanskrit (Devanagari), IAST, English meaning, physical-action diagram (ASCII).
2. Coach speaks the instruction in English via Piper (e.g., "Sit facing east. Sip water from your right palm three times as I chant.").
3. Play the canonical mantra audio from `assets/mantras/<mantra_id>.wav`.
4. Branch by `advance_rule`:
   - `auto` → wait `mantra_duration + 1.5 s`, then advance.
   - `user_confirm` → wait for student to say "next" / "ready" / "தயார்" (STT match against a small grammar). Spacebar fallback in TUI.
   - `recitation_match` → record student's recitation (VAD-bounded, max 60 s), STT it, compute phonetic similarity against `expected_recitation`. If ≥ threshold → advance with praise. Else → LLM picks the most-mispronounced segment and the coach gently re-models that fragment (slow Piper + slow mantra clip), then retries up to 3× before offering "shall we continue?".
5. Log every transition to `~/.local/share/sandhyavandanam_guru/sessions/<ts>.jsonl` for the user's review.

The LLM only ever sees a **structured prompt** with the current step ID, the diff between expected and heard text, and a temperature-zero instruction to produce JSON `{tone, message, action: "retry"|"advance"|"skip"}`. It cannot reorder steps, invent mantras, or skip the framework.

## Pronunciation-feedback approach

- Force Whisper to `language="sa"` (Sanskrit) so it does not Romanise into English words. Use `initial_prompt` containing the expected mantra in Devanagari — Whisper conditioning will sharply improve recognition.
- Convert both expected and heard to IAST via `indic-transliteration` (a mature library) and reduce to a phoneme stream (collapse vowel length distinctions optionally, keep retroflex/aspirated distinctions).
- Edit distance with a weighted cost matrix: cheap for vowel-length swaps, expensive for missing aspirate / retroflex / visarga (since those are the religiously meaningful errors).
- Threshold: ≥ 0.85 normalized similarity to auto-advance; 0.6–0.85 → "close, let's polish [fragment]"; < 0.6 → re-model from scratch.

## Voice agent failure modes already mitigated

Findings from the LiveKit, future.agi, and assemblyai turn-detection writeups, applied here:

- **Mantras have long internal pauses** → silence threshold raised to 1.4 s while in a `recitation_match` step; standard 0.5 s otherwise. Use silero-VAD plus a "still-chanting" heuristic (energy in low-pitch band).
- **Barge-in during guru playback** → student saying "stop" / "wait" / "மீண்டும்" cancels TTS + mantra playback in < 200 ms (Pipecat-style cancellable frames).
- **Whisper false transcriptions on silence** → drop transcripts whose avg-logprob < −1.0 or no-speech-prob > 0.6.
- **LLM stalls** → 8-second hard timeout on the LM Studio HTTP call; on timeout, fall back to a hard-coded gentle correction template per step.
- **No mic / LM Studio not running / no model loaded** → `scripts/doctor.py` (runs `lms ps` + `curl /v1/models`) and a TUI-mode-only ("read along") fallback that disables STT.

## Phased delivery (terminal-app first, per the spec)

**Phase 0 — bootstrap (small)**
- `pyproject.toml`, `README.md`, `scripts/doctor.py`, CI-less local lint via ruff + pytest.

**Phase 0.5 — Sanskrit STT shootout (one day, ~60 short clips)**
- Record the eval set (user + Claude-assisted target text list).
- Run Whisper-Sanskrit and Gemma 4 E4B audio on each clip.
- Produce `docs/stt_decision.md` with the per-model CER, religious-error recall, latency. Set the winner as the default STT in `config.py`. *Skippable if the user is fine starting with Whisper-Sanskrit as the safe default.*

**Phase 1 — ritual content & TUI skeleton**
- Write `ritual/pratah_rigveda.yaml` with all 26 steps + IAST + translations.
- `ritual_loader.py` + tests.
- Textual TUI that lets the user step through with arrow keys (no audio yet). This is independently usable as a study aid.

**Phase 2 — guru voice (coach TTS only)**
- Piper integration, instruction lines per step authored in `ritual/coaching_en.yaml`.
- Player with cancellable playback.
- TUI now reads each step aloud; still no listening.

**Phase 3 — mantra bank**
- `scripts/build_mantras.py` renders each unique mantra once via Svara-TTS, saves to `assets/mantras/`. Document how a user can drop in their own priest-recorded `.wav` (same filename) to override.

**Phase 4 — listening & feedback**
- VAD + faster-whisper wired in.
- `phonetics/similarity.py` + tests with golden recordings.
- Hook `recitation_match` advance rule.

**Phase 5 — LLM coach polish**
- LM Studio client + prompts (`openai` SDK pointed at `http://localhost:1234/v1`).
- LLM-authored gentle feedback, language switch (English ↔ Tamil) via a single `--lang` flag.
- Session log + summary screen at the end.

**Phase 6 — robustness**
- `doctor.py` checks; graceful degradations (no mic, LM Studio offline, no Svara model).
- Settings file for thresholds.

Phases 1–2 are independently demoable; the spec's "simple TUI/console app first" goal is met after Phase 2.

## Verification (end-to-end)

For each phase, manual + automated:

- `pytest -q` for unit tests (loader, similarity, engine transitions).
- `python -m sandhyavandanam_guru.cli --dry-run --no-audio` walks all 26 steps in the terminal, asserting no exceptions and that every step has a non-empty instruction + mantra reference.
- `python scripts/doctor.py` verifies: Python ≥ 3.11, LM Studio HTTP server reachable at `http://localhost:1234/v1/models` and the chosen model is loaded (`lms ps`), Piper voice file present, mantra bank ≥ N files, default input/output audio device discoverable.
- `python -m sandhyavandanam_guru.cli` (full run) on a Mac:
  - Hear Piper coach a step.
  - Hear a mantra play back.
  - Speak the mantra into the mic; observe similarity score and the coach's response.
  - Use the spacebar to advance manually; use the "stop" voice barge-in to interrupt.
- Session log under `~/.local/share/sandhyavandanam_guru/sessions/` should show every transition with timestamps, similarity scores, and any LLM feedback.

## Explicit non-goals (Phase ≤ 6)

- Madhyāhna and Sāyaṃ rituals (architecture supports them via new YAML; not delivered now).
- Voice cloning of the user's own voice (Svara-TTS supports it, but mantra correctness > personalisation).
- GUI / mobile / web. Terminal only, per spec.
- Cloud TTS/STT. Everything runs locally.
